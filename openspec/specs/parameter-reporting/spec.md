## Requirements
### Requirement: Parameter labels are unambiguous
The system SHALL avoid generic `Params` or `Head Params` labels in rebuttal-facing outputs and use `Trainable Params` and `Total Params` as separate fields.

#### Scenario: Generate parameter output
- **WHEN** a P0 reporting command emits parameter counts
- **THEN** the output contains distinct `Trainable Params` and `Total Params` labels

#### Scenario: Generate table template
- **WHEN** a rebuttal table template includes parameter counts
- **THEN** it labels trainable and total parameter columns separately

### Requirement: Total parameters include frozen VFM
The system SHALL define `Total Params` as all model parameters, including the frozen vision foundation model.

#### Scenario: Count total parameters
- **WHEN** total parameters are computed for a model
- **THEN** the count includes frozen backbone/VFM parameters as well as trainable decoder, SASA, GGSF, and in/out head parameters

### Requirement: Trainable parameters reflect actual optimization surface
The system SHALL define `Trainable Params` as parameters with `requires_grad=True` after the model is constructed with its intended frozen-backbone configuration.

#### Scenario: Count trainable parameters
- **WHEN** trainable parameters are computed for a model
- **THEN** the count includes only parameters that would be optimized in the intended training configuration

### Requirement: No fabricated parameter or metric values
The system SHALL leave table values as placeholders until generated by a command output or supplied by the user from the server.

#### Scenario: Missing server output
- **WHEN** no server-produced output is available for a table cell
- **THEN** the table cell remains `TBD` rather than using estimated or invented values
